What works, what is halfway, and what needs attention. "Tested" means automated tests ran in a copy of the app with a fake Supabase and fake AI. "Live" means checked against the real site at hiba-neon.vercel.app.

## 2. Halfway or not built

| Item | State | Note |
|---|---|---|
| Account deletion | **Not built** | The Privacy Policy (section 8) and Terms (section 12) say you can delete your account at any time. Deleting the login needs Supabase's admin key, which Hiba never uses. **Owner decision needed:** a small admin-only function, or a "request deletion" email flow handled by you. |
| Scheduling and automatic publishing | Not built | Settings and Home say so plainly. Every post waits for approval. |
| Comment posting | Works only while the page is open | Closing the tab pauses it; reopening resumes. Fully background posting would need a scheduled server job. |
| X and Substack publishing | Copy only | No connection offered; the app says so. |
| Calendar, Images page, Assistant | "Coming soon" pages | Plain wording, nothing broken. |
| Notifications | None | Settings says so. |
| Landing page | Minimal (HPD-155) | Its "placeholder" wording is fixed in this PR. |
| Public profile page | Not built | It used to show "placeholder". It now says plainly that profiles are not available yet. |

## 3. Security

| Check | Result |
|---|---|
| Row Level Security on every table | Yes, in every migration; one person cannot read or change another's rows (local database tests) |
| Admin (service_role) key | Never used, in the app or in functions |
| Secrets in the website code | None (live bundle checked) |
| `.env` in git | No (`.gitignore` blocks it) |
| Images bucket | Private, with signed links that last 1 hour (live checked) |
| Rate limits | Drafts, transcription, LinkedIn publishing (per hour) and comments (30 per hour) |
| Input validation | In the database (lengths, statuses, allowed transitions) and in the functions |
| Security headers | HSTS, X-Frame-Options, nosniff, Referrer-Policy and Permissions-Policy were already live. **Added in this PR:** Content-Security-Policy |
| Which websites may call the functions | It was any website. **Fixed in this PR:** only addresses in the `APP_ORIGINS` secret. Every call also still needs your login. |
| Dependencies | **Fixed in this PR:** 2 high-severity issues in development tools (Vite, source-map-js). The live site was never affected. `npm audit`: 0. |
| Prompt injection | Ideas, samples and posts are marked as content, never instructions, in every prompt |

Not verifiable from here (Supabase dashboard settings): email confirmation, password strength rules, leaked-password protection, and auth rate limits. They are worth a look under Authentication → Settings.

## 4. Fixed in this PR

1. Content-Security-Policy header. Tested on a production build with the policy switched on: 9 browser test suites, 0 blocked resources. A deliberately broken policy was caught (10 blocked images), which proves the check works.
2. Function CORS limited to `APP_ORIGINS` in `generate-drafts`, `linkedin` and `transcribe` (18/18 checks).
3. Dependency vulnerabilities: 0 left.
4. Wording:
   - Home no longer says "post them yourself until you connect your accounts".
   - The landing page and public profile pages no longer show "placeholder".
